# Documentation internationalization

## Supported languages

Public, human-facing documentation for Post-Training RSI Pipeline supports:

- English (`en`) as the canonical technical language;
- Traditional Chinese (`zh-TW`) as a maintained peer translation.

The root README and community health documents must have reciprocal language links and should be updated in the same Pull Request.

## File naming

| English | Traditional Chinese |
|---|---|
| `README.md` | `README.zh-TW.md` |
| `CONTRIBUTING.md` | `CONTRIBUTING.zh-TW.md` |
| `docs/README.md` | `docs/README.zh-TW.md` |
| `path/name.md` | `path/name.zh-TW.md` |

Do not use locale suffixes for machine contracts, code, JSON, YAML, schema IDs, CLI names, State Machine states, digest fields, or stable artifact identifiers.

## Translation contract

A translation must preserve:

- claim strength and evidence level;
- warnings, limitations, non-goals, and failure behavior;
- commands, paths, identifiers, version constraints, and links;
- security, privacy, licensing, and data-handling requirements;
- tables, diagrams, acceptance criteria, and responsibility boundaries.

Technical identifiers remain unchanged when translation could break copy/paste or alter semantics. Explanatory prose may include the English term on first use.

## Controlled exceptions

The following Markdown classes are not rewritten or duplicated automatically because language changes can alter execution, provenance, or evidence:

- `AGENTS.md`, `CLAUDE.md`, `SKILL.md`, and other executable Agent instruction contracts;
- generated cards, model outputs, receipts, fixtures, snapshots, replay artifacts, and signed evidence;
- vendored third-party notices or upstream documentation;
- archived historical records whose byte identity is part of the evidence.

These files must be reachable from a bilingual index. Human-facing summaries may be translated, but the canonical artifact remains unchanged and its status must be stated.

## Review and CI

`docs/i18n-manifest.json` lists the maintained document pairs. `scripts/check_docs_i18n.py` verifies that each pair exists, carries a matching i18n key, and includes reciprocal navigation. CI checks structure, not semantic translation quality; reviewers remain responsible for parity.

A new public document must either:

1. add both language versions and register the pair;
2. be intentionally bilingual inline and registered;
3. be listed as a controlled exception with a reason.

Silent English-only public documentation is not accepted.
